## 5. 固定样例内容核查

第一轮固定样例为 **3 份代码 × 4 类分析 = 12 份预置报告**，均经过 Pydantic 校验，
并人工核对了以下要点：

| 样例 | 核对内容 |
|---|---|
| Python 两数之和 | 双重循环 O(n²)、空数组/单元素/无解返回 `None`、重复元素用例、返回顺序未定义 |
| Java 数组统计 | 空数组除零、`int` 除法截断、全负数最大值错误、`int` 累加溢出、null 指针 |
| C++ 二分查找 | 空数组 `size()-1` 无符号下溢、`(left+right)/2` 溢出、未排序输入、`using namespace std` |

核验方式：

- 所有 `line` 字段均落在对应代码行数范围内（`test_demo.py::test_key_lines_stay_within_code_range`）；
- 代码片段与原始样例逐字一致；
- 测试用例的预期结果与代码实际行为或接口约定一致；对会暴露缺陷的预期值已在备注中说明
  “当前实现返回 …”。

局限：12 份样例的规模小于需求建议的 20–30 个固定问题，后续可扩充更多算法与缺陷类型，
并引入人工评分表比较“格式完整”与“内容正确”。

## 6. 真实模型连通性验证步骤（待执行）

在配置有效 API Key 后建议执行：

1. 选择 `CODEINSIGHT_PROVIDER=openai`，配置官方或兼容服务 Base URL；
2. 分别用三份内置示例运行四种模式，检查：

   - 审查问题是否与样例中预埋的风险一致；
   - 测试用例接口与预期结果是否符合代码行为；
3. 断开网络或填写错误 Key，确认界面显示可读错误且“重试分析”可用；
4. 使用一个会返回非 JSON 内容的模型（或临时修改提示词），确认解析修复与原始输出展示；
5. 使用 Ollama 本地模型重复第 2 步，对比输出差异。

## 7. 已知限制

1. **真实在线调用未在本环境执行**：无 API Key，在线路径由假模型覆盖；上线前需补做连通性验证。
2. **结构正确 ≠ 内容正确**：Pydantic 校验只能保证字段与类型，无法保证模型分析结论的事实准确性；
   固定样例用于部分缓解，但仍需人工评估。
3. **离线演示仅支持内置样例**：避免把固定报告错误地展示为对用户代码的分析。
4. **不执行代码**：测试用例的预期结果由模型推导，未经过实际运行；语法错误判断不等同于编译器。
5. **未实现历史记录与账号体系**：刷新或重启后结果不持久化。
6. **性能**：输入上限 20,000 字符；模型延迟取决于服务商，超时默认 90 秒。
